---
title: appo ship
description: Pubblica un'app sugli store con un solo comando.
---

`appo ship <id>` porta sugli store un'app esistente. Segnala l'intenzione di
pubblicazione: Appo avvia la build lato server, la invia in revisione e
gestisce la pubblicazione operata. L'app si crea prima con `appo new`, che ne
stampa l'id.

```bash
appo new --url https://example.com --name "My App"
appo ship <id>
```

## Cosa succede

1. La CLI si ferma a un gate di conferma e mostra cosa verrà pubblicato.
2. Alla conferma, Appo esegue la pubblicazione: build, invio agli store,
   revisione Apple, aggiornamenti.

Passa `--yes` per saltare il gate di conferma (pipeline CI) e `--stores <list>`
per limitare gli store di destinazione.

## Ripubblicare e inviare di nuovo

Lo stesso comando ripubblica un'app, incluso il nuovo invio dopo un rifiuto
dall'App Store. Combinalo con:

- `appo status <id>` — stato di pubblicazione e azione successiva.
- `appo rejection <id>` — il rifiuto attivo dall'App Store, se presente.
- `appo fix-recipe <id>` — la soluzione suggerita per quel rifiuto.

## Anteprima prima di pubblicare

`appo run [id]` avvia una build TestFlight se non ce n'è una pronta, poi mostra
la destinazione di anteprima per il tuo telefono (link TestFlight o deep link
Android, con QR code). Senza id usa la tua unica app, oppure mostra un
selettore.
