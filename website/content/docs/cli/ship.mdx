---
title: appo ship
description: Publish an app to the stores with one command.
---

`appo ship <id>` takes an existing app to the stores. It signals publish
intent: Appo issues the build server-side, submits it for review and operates
the publication. The app is created beforehand with `appo new`, which prints
its id.

```bash
appo new --url https://example.com --name "My App"
appo ship <id>
```

## What happens

1. The CLI stops at a confirm gate and shows what will be published.
2. On confirmation, Appo executes the publication: builds, store submission,
   Apple review, updates.

Pass `--yes` to skip the confirm gate (CI pipelines), and `--stores <list>`
to restrict the target stores.

## Republishing and resubmitting

The same command republishes an app, including resubmission after an App Store
rejection. Pair it with:

- `appo status <id>` — publication state and the next action.
- `appo rejection <id>` — the active App Store rejection, if any.
- `appo fix-recipe <id>` — the suggested fix for that rejection.

## Preview before shipping

`appo run [id]` triggers a TestFlight build if none is ready, then shows the
on-device target for your phone (TestFlight link or Android deep link, with a
QR code). With no id it uses your only app, or shows a picker.
