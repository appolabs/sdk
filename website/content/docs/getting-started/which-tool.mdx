---
title: SDK, CLI or MCP?
description: Three surfaces, one platform — which one you need and when.
---

Appo ships three developer surfaces. They are complementary, not
alternatives: most projects end up using the SDK inside the app and the CLI
or MCP around it.

| | SDK | CLI | MCP |
| --- | --- | --- | --- |
| Package | `@appolabs/sdk` | `@appolabs/appo` | `@appolabs/appo-mcp` |
| What it is | JavaScript bridge inside your web app | Terminal client for the app lifecycle | The same lifecycle, driven by an AI assistant |
| Use it to | Call native APIs (push, biometrics, camera, GPS) from your web code | Create, ship, publish and monitor apps from the terminal or CI | Let your agent create, ship and manage apps for you |
| Install | `npm install @appolabs/sdk` | `npm install -g @appolabs/appo` | `claude mcp add appo -- npx -y @appolabs/appo-mcp` |
| Start here | [Installation](/sdk/installation) | [CLI](/cli) | [MCP server](/mcp) |

A rule of thumb: the SDK lives in your app's code; the CLI and MCP live in
your workflow. If you never open a terminal, the dashboard covers everything
the CLI does.
